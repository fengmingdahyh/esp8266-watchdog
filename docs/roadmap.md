## 一、最疼的三处（半天内能上，风险低）

### 1. 健康 / 复位原因卡片 —— 优先级最高 ✅（v1.2 已实现）

现在“网页打不开”只能靠串口抓日志，一个没有串口的人（或者半夜）根本判断不了。
把板子自己知道的东西暴露出来，成本极低：

| 字段 | 来源 | 为什么有用 |
| --- | --- | --- |
| `reset_reason` | `ESP.getResetInfoPtr()->reason` | 区分 上电 / 看门狗复位 / 软件重启 / 异常 |
| `reset_exccause` | 同上 `exccause` | 异常复位时直接给崩溃类型 |
| `heap_free` / `heap_frag` | `ESP.getFreeHeap()` / `ESP.getHeapFragmentation()` | 碎片率 > 70% 就是“该重启了”的信号 |
| `wifi_drops` / `sta_tries` | 自己在 `loop()` 里计数 | 判断是不是信号问题在反复掉线 |
| `last_probe_err` | 记录最近一次探测失败是 DNS 还是 TCP | 断网时能分清“路由器挂了”还是“外网没了” |

```cpp
// /api/health
rst_info *r = ESP.getResetInfoPtr();
j += "\"reset_reason\":" + String(r->reason) + ",";
j += "\"reset_exccause\":" + String(r->exccause) + ",";
j += "\"heap_frag\":" + String(ESP.getHeapFragmentation()) + ",";
j += "\"wifi_drops\":" + String(wifiDrops) + ",";
```

页面：看板底部加一行小字 `复位: 上电 · 碎片 42% · 掉线 3 次 · heap 36.1KB`。
**验收**：拔电重插 → 显示 `上电(0)`；网页点“重启” → 显示 `软件重启(6)`。

### 2. 断网事件落盘 `/outages.bin` ✅（v1.2 已实现）

现在“断网记录”只活在内存里，一重启就没了——而这正是用户最想回头看的东西。

```cpp
struct Outage { uint32_t startTs; uint16_t durSec; uint8_t rssi; };   // 7 B
// 环形 40 条 = 280 B，一次写整个文件，别每条写一次
```

- 只在 **断网结束**（恢复那一刻）写盘一次，不在每次采样写 —— LittleFS 是按块擦写，写放大很凶。
- `GET /api/outages` 返回最近 40 条，页面时间线直接渲染。
- **验收**：拔网线 2 分钟 → 恢复 → 断电重启 → 页面仍能看到这条记录。

### 3. 主 / 备 WiFi（多 SSID）✅（v1.2 已实现）

现在只有一组 SSID，主 WiFi 一旦挂了（或路由器在重启）设备就永久卡在配网模式。
- config 增 `ssid2` / `pass2`，`startSta()` 里按顺序尝试，每个给 25 秒预算（总预算仍 45~50 秒）。
- 配网页加一个“备用 WiFi”折叠区，`/api/scan` 现成能用。
- **验收**：把主 SSID 改成不存在的名字 → 自动连上备用 → 看板显示备用 SSID。

## 二、观测类（最实用，1~2 天）

### 4. 延迟分位 / 抖动 ✅（v1.2 已实现）
- `p50 / p95 / max / jitter`（相邻采样差的绝对值均值），只遍历 720 个点算一次，毫秒级。
- 看板“当前延迟”那格改成可切换：实时 / p95 / 抖动。
- 价值：平均 45 ms 但其实 p95 300 ms 的线路，比“可用率 100%”更说明问题。

### 5. 每日报告推送 ✅（v1.2 已实现）
- 已具备 NTP（`timeReady`），每天 `08:00` 用现成的 Server 酱通道推一条：
  `昨日可用率 99.8% · 断网 2 次(共 7 分钟) · 平均 46ms · p95 210ms · 最长断网 5 分钟`
- 注意：只在 `timeReady && netOk` 时推；推送失败不重试，别把配额烧光。

### 6. CSV 导出 ✅（v1.2 已实现）
- `GET /api/history` → `时间戳,延迟,在线` 全量 720 行。
- **别拼成一个 14 KB 的 String**（heap 会碎），按 512 B 分块 `sendContent`，复用 `sendFileSafe` 思路。

### 7. 分层断网判断 ✅（v1.2 已实现）
- 现在 DNS+TCP 都失败才算断网。加一条“网关 ping 失败 = 局域网断”，推送文案分两种：
  `🔴 路由器/局域网断开` vs `🔴 外网中断（路由器在线）`。
- 家庭场景里这两种的处置完全不同（一个去重启路由器，一个打运营商电话）。

## 四、好玩，但有代价（未做）

### 8. WOL 网络唤醒
局域网发 magic packet 唤醒 NAS/台式机。很贴“家庭网络工具”的人设，代码 ~40 行（UDP 9，6×0xFF+16×MAC）。
代价：得在网页存 MAC 地址列表（Flash 一点点），并且只对有线网卡有效。

### 9. heap 看护 / 定时重启 ✅（v1.2 已实现）
`heap < 6 KB` 持续 5 分钟 → 记一条原因 → 重启。ESP8266 跑久了碎片化是必然的，
主动重启比某天自己崩掉好。用 §1 的 `reset_reason` 区分“看护重启”和“异常”。

### 10. 端口探测面板
自定义 3 条 `host:port`（路由器 80、NAS 5000、打印机 9100），断网时能立刻看出是“整个网挂了”还是“某个服务挂了”。
代价：每条一次 TCP 连接，别放在 60 秒主循环里同步做，错开到不同 tick。

## 五、不建议做（会翻车）

- **内置 speedtest**：ESP8266 的 RAM 和带宽都撑不住，跑一次会把看板卡死十几秒。
- **把历史点从 720 加大**：`Rec` 7 B × 720 ≈ 5 KB 静态 RAM，加到 2000 点直接吃掉 14 KB，82 KB 的堆经不起。
- **在 config.txt 里塞更多密钥**：现在 `sendkey` 已是明文，再加 webhook/token 只是扩大泄露面；
  真要加强就先做“config 简单异或 + 只读回显”，别加新密钥。
- **页面里做实时流量图 / WebSocket**：轮询 5 秒已经够，WebSocket 会常驻一个连接和缓冲区。

## 六、推荐 v1.2 打包（一次编译一次刷机）

| 顺序 | 内容 | 理由 | 预估代价 |
| --- | --- | --- | --- |
| A | 健康/复位卡片 + heap 看护 | 以后排障直接从“抓串口”变成“看页面” | +2.5 KB Flash / +0.3 KB RAM |
| B | 断网事件落盘 + CSV 导出 | 数据不再随重启蒸发，且能拿出去分析 | +2.5 KB / +0.4 KB |
| C | 主/备 WiFi | 直接治“路由器一重启设备就掉线” | +1.5 KB / +0.2 KB |
| D | 每日报告推送 | 现成通道，边际成本最低的“有感知”功能 | +2 KB / +0.3 KB |

合计约 **+8.5 KB Flash（仍 ~48%）、+1.2 KB RAM**，heap 仍剩 35 KB 左右，安全。

### 共同注意（踩过的坑）

- 写盘一律“攒够再写、整文件覆盖”，别在循环里 `open/write`；`hist.bin` 每 10 点一次的策略继续沿用。
- 拼 JSON 用 `String` 会碎片化，超过 1 KB 的响应改成固定 `char buf[512]` 分块发。
- 任何新加的 HTTP 处理都必须先 `checkAuth()`，并且不能阻塞超过 ~2 秒（否则看板 5 秒轮询会叠起来）。
- OTA 之后 `esp_restart` 前不要再开文件写，否则容易把 FS 写坏。
