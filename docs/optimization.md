# WatchDog 优化建议清单

> 基于 Server 酱断网推送功能上线后的现状，列出值得考虑的改进项。
> 每条都标了优先级与工作量，按需挑选，不影响当前运行。

> **落地情况**：§1 版本号已升；§2 推送文案已按“局域网断/外网断”分层；
> §4 恢复推送已带“本次断网 XX 秒”；§7 的 OTA / 可视化部分仍未动；
> **§5 的「设网页密码」已实现**（v1.3.2）。
> 额外落地了健康/复位页、断网事件落盘、主备 WiFi、每日 08:00 简报、p95/抖动、CSV 导出、固定 IP。

---

## 1. 版本号升级（随手可做）✅

**现状**：`FW_VERSION` 定义在 `WatchDog/WatchDog.ino` 顶部。功能级更新时记得升版本号，方便从日志/页面区分新旧固件。

## 2. 推送文案优化（可随时改）

**现状**：断连/恢复文案已含时间、SSID、IP、信号、延迟。可继续打磨：

- **标题带可用率/持续时间**：断连推送加上“已离线 XX 分钟”（记录离线开始时间戳），恢复推送带上“本次断网持续 XX 分钟”。对“家里断网多久”这类问题更有价值。
- **断网记录数**：文案末尾带上 `断网记录累计 N 次`（历史数组里有数据）。
- **测试推送区分来源**：测试推送标题已是“✅ WatchDog 测试推送”，与恢复推送（“✅ WatchDog 网络恢复”）可区分，够用。
- **注意**：Server 酱免费额度有限，状态翻转推送已是防刷屏的正确做法（只推一次），不要改成“每次探测失败都推”。

## 3. 断网判定与推送时机（当前是设计行为，明确一下）

**现状**：连续 2 次探测失败（约 2 个周期 ≈ 120 秒）才判离线并推送。好处是抗单次抖动；代价是断网通知有 ~2 分钟延迟。

可选改进（需权衡）：
- **首次失败立即提示**：把“连续 2 次”降为“1 次即判”→ 更敏感，但路由器重启、WiFi 漫游时的瞬断会误报。
- **双阈值**：1 次失败推“可能断网”（标题用“⚠️”），恢复后再推一条澄清——复杂化，不建议。
- **建议保持现状**：2 次判离线 + 状态翻转推送，是家庭场景最稳的平衡点。

## 4. 推送可靠性增强（中优先级）

**现状**：`pushServerChan` 超时 8 秒、HTTP 200 算成功，失败不重试不记录。

建议：
- **失败重试 1 次**：首次失败隔 30 秒重试一次（断网时设备本身无外网，重试价值有限，但 WiFi 恢复瞬间第一次 POST 常因未就绪失败，值得）。
- **失败串口记录**：现在已有 `[push] ... -> HTTP xxx` 日志，保持即可。
- **恢复推送“尽力而为”**：若设备刚连上 WiFi 就推恢复，DNS/路由可能还没通，可在恢复推送前 `delay(3000)` 或先 ping 一次再推。

## 5. SendKey 安全（低风险，提一句）

**现状**：`sendkey` 明文存在 `data/config.txt`。

- 风险点：SendKey 等于 Server 酱账户的推送令牌，泄露后别人可冒充你推送。
- 建议：不要把 `filesystem.bin` / `config.txt` 发到公共网盘或提交进公开仓库；如怀疑泄露，去 Server 酱后台重置 SendKey 并改 config。
- 网页密码（webpass）目前为空——**建议在设置页设一个**，否则局域网内任何人都能改配置、触发测试推送。

## 6. 网页端小改进（低工作量）

- **显示 SendKey 是否配置**：`cfgTip` 已显示“已配推送/已设密码”，够用。
- **测试推送按钮防抖**：已实现（发送中置灰），OK。
- **保存后提示**：目前保存即重启，断网 5-10 秒属正常，网页端可加“正在重启…”过渡文案（当前是直接没响应，容易误以为失败）。

## 7. 长期可做（不影响使用，按需）

- **OTA 验证**：固件已带网页 OTA（Updater），可在 files.html 页面验证一次整包 OTA，以后改固件不用开串口盒。
- **可用率/断网记录可视化**：看板已有“24h 可用率 / 断网记录”区块，历史数据掉电落盘已实现，可考虑加“最近 30 天可用率”趋势。
- **断电数据可靠性**：historySave 每 10 次采样落盘，断电最多丢 ~10 分钟数据，可接受。
- **电源**：WeMos D1 的 USB 供电在路由器 USB 口可能不稳（WiFi 发射电流尖峰），若偶发重启，换 5V/1A 独立电源。
- **信号**：若看板放远了信号变差，可考虑外接天线（D1 板载陶瓷天线）或挪位置。

## 8. 维护流程建议（配套手册）

- 每次改固件：改代码 → `arduino-cli compile`（命令见 `docs/build-and-flash.md` §5）→ 产物改名 `WatchDog.bin` → 按需打包 FS → 烧录 → 复位抓 boot 日志 → `GET /api/config` 确认。
- 每次改网页：改 `data/` → mklittlefs 重新打包（-b 8192 -p 256 -s 0xFA000）→ 只烧 0x300000。
- **任何一步验证不通过就停下来排查，不要带病上线**——历史教训：FS 打包参数错 → 设备“看似正常”但网页全挂。

## 优先级汇总

| 优先级 | 事项 |
|---|---|
| 高 | 设网页密码（webpass）✅ v1.3.2 |
| 高 | 版本号管理 + boot 日志带 has_sendkey ✅ |
| 中 | 推送失败重试 1 次、恢复推送前小延迟 |
| 中 | 断网推送加“已离线 X 分钟”、恢复带“本次断网持续” |
| 低 | 保存重启过渡文案、OTA 实测、可用率月趋势 |
